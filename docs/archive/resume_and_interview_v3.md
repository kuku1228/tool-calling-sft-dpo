## 一、简历条目（Agent / LLM 算法岗）

**航空客服工具调用 Agent 的评测体系、训练语料诊断与偏好优化** ｜ 个人项目

- **构建了工具调用 Agent 的完整优化与评测闭环**：自建 106 任务基准（8 类，
  含多步、多工具、多轮改主意、错误纠正）→ 逐任务错误分类（5 类互斥 + 12 子类型）
  → 偏好数据构造 → SFT/DPO 训练 → 单轮与多轮双轨评测。

- **把 Qwen2.5-1.5B 在自建基准上的准确率从 28.0%（真实基线）提升到 95.3%**
  （pass^4 ~93%，簇级口径 ~94%）。其中三个类别从 **0% 提升到 93~100%**。

- **发现并修复了一个会虚高准确率的评分漏洞**：「应先追问」任务的判据仅检查
  「未调用工具」，导致**空输出被判为正确**。未训练基座因此在该类任务上
  「通过 98.2%」，使总体准确率虚高 **14 个百分点**。修正后的真实基线是
  **28.0%（91 个需调用工具的任务）**，而非 37.97%。

- **定位并修复了训练语料的「技能缺口」**：语料覆盖了全部 52 个机场码
  （实体覆盖检查全绿），但**带观测轮的多步任务 0 个、多工具任务 0 个**
  —— 而评测有 31 个带观测轮的任务、10 个 multi_tool 任务，导致三个类别准确率为 0%。
  补齐后（语料 181 → 247 任务）升至 93~100%；其中 `flight_search`
  **未补专类语料也升至 100%**（技能迁移）。

- **通过受控实验确立机制：SFT 学到的是「全局决策倾向」而非「条件规则」**。
  同一模型、同一任务集、同一超参，只改训练数据里「不应调用工具」的**占比**
  （`chosen` 不含 `tool_call`：0.0% → 12.1%），「该不该调用」边界任务的准确率
  从 **31.8% → 95.5%**，而需调用工具的任务保持 ~95%。
  该占比（12.1%）与评测中该类任务占比（14.2%）匹配，说明是**条件规则可学**
  而非数据量压倒。

## 二、面试问答（预定口径）

### Q1 「这个项目做了什么？」

自建工具调用基准 + 完整优化闭环，把 1.5B 模型从真实基线 28.0% 提到 95.3%。

**主动说明**：这个项目**一半的工作量在评测可信性**上 —— 我查出并修复了
**8 类会让结论作废而不报错的缺陷**（见 §三）。因为那些缺陷不修，
所有准确率数字都不可信。

### Q2 「为什么强调『真实基线 28.0%』而不是 37.97%？」

因为 37.97% 里约 **14 个百分点是免费的**：「应先追问」任务的判据只是
「没有 `tool_call`」，而**未训练基座几乎不调用工具**，于是在这 15 个任务上
白拿 98.2%。

**修正后**：它在 91 个真正需要调用工具的任务上只有 **28.0%**。

**这个发现的价值**：任何用「未调用工具即正确」当判据的工具调用评测，
都会把**不作为**误判为**正确**。

### Q3 「为什么三个类别一开始是 0%？」

不是模型能力问题，是**训练语料的技能缺口**：

```
训练语料里带观测轮的多步任务:  0 / 181
训练语料里 multi_tool 任务:    0 / 181
而评测有 31 个带观测轮的任务、10 个 multi_tool 任务
```

原来的实体覆盖检查**全绿**（52 个机场码都在），但**技能是 0**。
所以我给断言加了技能检查：现在缺技能会直接抛错。

**一个反直觉的点**：`flight_search` 我没补专类语料，它从 0% 涨到 100%
—— 因为「读观测取参数」这个技能迁移过去了。

### Q4 「你的核心发现是什么？」★

**SFT 学到的是「全局决策倾向」，不是「条件规则」。**

证据是两段独立的实测，方向相反：

| 实验 | 训练里「不该调用」占比 | cancellation |
|---|---|---|
| `sft_only` | **0.0%** | 31.8% |
| `sft_clarify` | **12.1%** | **95.5%** |

**同一个模型、同一个任务集、同一个超参，只改这一个变量。**

模型的决策倾向由**训练数据里各动作的相对频率**决定，
而不是由任务本身决定。正例只告诉模型「该怎么做」，
**不告诉它「什么时候不该做」**。

### Q5 「为什么不做 DPO？」

**做了** —— 早期 6 组 DPO 实验的结果因**数据污染**被整体作废
（1292/2509 训练样本与评测 prompt 逐字相同），我已推翻并重建。

**重建后的结论**：在补足训练语料覆盖之后，**SFT 已到 95.3%**，
剩余失败 4.7% 中**决策类错误只有 1/424**。DPO 的增量空间很小。

**表述**：原本假设 DPO 在「否定性约束」上有独特价值，
但实测显示**这个价值可以通过「在 SFT 数据里加入负例的 chosen」实现** ——
也就是说，**起作用的是数据覆盖，不是训练算法**。这个结论比原假设朴素，
但更可复现。

### Q6 「你踩过哪些坑？」★（这题最能体现能力）

**8 类不报错但会让结论出错的缺陷**：

| # | 缺陷 | 症状 |
|---|---|---|
| 1 | 训练数据含评测任务 | 准确率**更高**（95% 虚高） |
| 2 | 空输出判为正确 | baseline 虚高 14pp |
| 3 | 机场码两处漂移 | 33 个码模型从未见过 → `flight_search` 59% |
| 4 | 训练语料零多步任务 | 三个类别 0%，而实体覆盖检查**全绿** |
| 5 | 追问样本未进 SFT | 补了语料但 pair_type 不含 `clarify_boundary`，**白跑 30 分钟** |
| 6 | 期望值不可推导 | 2 个任务**永远答不对**，被记成「模型参数错」 |
| 7 | 一致性检查器假通过 | 报「✓ 一致」但实际只比对了前 400 字符 |
| 8 | 循环导入 | 7 个测试**静默不注册**（测试数少但**不报错**） |

**共同点：全都不报错。** 数字正常、loss 正常、测试通过，而结论是错的。

**修法**：每条都配一个**能失败的检查**，并**给检查器本身写反向测试**
（喂入已知坏数据，确认它真的报警）。

### Q7 「这个项目的局限？」

我会**主动**说三条（由 `src/eval/limitations.py` 自动生成）：

1. **`seen`/`unseen` 标签没有含义** —— 它从不读取训练数据，
   实测 `unseen` 组签名也被训练覆盖 38/38。所以**不能**用它讲泛化。
2. **有效独立样本少于表面样本** —— 106 个任务只有 92 个不同期望调用；
   15 个 clarify 任务的期望调用**完全相同**（都是「不调用工具」），
   有效样本是 **1 个行为**，15 是触发方式数。统计必须按**簇**重采样。
3. **训练分布与评测分布有偏差** —— `search_flights` 占训练 48.6%、
   占评测 30.2%。所以**绝对准确率不能外推**；但组间对比不受影响（偏差对称）。

## 三、写作注意（避免面试翻车）

| ❌ 不要写 | ✅ 应该写 |
|---|---|
| 「准确率提升 XX 个百分点」（引用旧任务集/污染数据的数字） | 「从 **28.0%**（真实基线）提升到 **95.3%**；旧数字已作废，见 `FINAL_REPORT_v3.md` 附录 A」 |
| 「15 个 clarify 独立样本」 | 「**1 个行为**在 15 种触发方式下验证；统计按簇重采样」 |
| 「seen/unseen 泛化」 | **不提**（标签无含义） |
| 「DPO 是唯一能编码否定性约束的方法」 | 「**在 SFT 数据里加入负例 chosen** 即可实现，起作用的是数据覆盖」 |
| 「agent 评测 100%」 | 若提，必须带「覆盖排除了 `flight_search`」 |
| 「CI 不重叠所以显著」 | 「**配对** bootstrap + McNemar」（CI 重叠不是判据） |

**主动说明局限比被追问出来更有利。**
每条结论都准备一句「这个数字的边界是……」，而**边界不清楚的结论就不写**。
