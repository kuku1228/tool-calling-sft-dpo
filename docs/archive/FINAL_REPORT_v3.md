## 0. 一句话结论

**在一个自建的工具调用基准上，把 Qwen2.5-1.5B 的准确率从 28.0%（真实基线）
提升到 95.3%。更重要的发现是：模型学到的是「全局决策倾向」而非「条件规则」——
同一模型、同一任务集，只改训练数据里负例的占比（0% → 12.1%），
决策行为就从「总是调用工具」翻转到「能区分该不该调用」。**

## 4. 核心发现：SFT 学的是「全局倾向」，不是「条件规则」

### 4.1 问题：纯正例监督在结构上无法表达否定性约束

实测 `sft_only` 的 2635 条里，`chosen` **不含** `tool_call` 的有 **0 条**：

```
sft_only     2635 条   不含 tool_call   0 (0.0%)
sft_clarify  2999 条   不含 tool_call 364 (12.1%)
```

**后果**：模型学成「总是调用工具」。在「应先追问」的任务上准确率只有 **31.8%**。

### 4.2 关键实验：只改「负例占比」，行为翻转

| 实验 | 训练数据里「不调用工具」占比 | cancellation | flight_search | multi_tool |
|---|---|---|---|---|
| `sft_only` | **0.0%** | 31.8% | 100% | 100% |
| `sft_clarify` | **12.1%** | **95.5%** | 100% | 100% |

**同一模型、同一任务集、同一超参，只改这一个变量。**

而且 `sft_clarify` 的追问样本只占 **12.1%**，评测里「应追问」任务占 **14.2%** ——
**比例匹配**，所以模型有能力学到条件规则，不是被数据量压倒。

### 4.3 机制解释

模型的决策倾向由**训练数据里各动作的相对频率**决定，而不是由任务本身决定：

```
训练里「不该调用」占 0%    →  模型从不追问   →  cancellation 31.8%
训练里「不该调用」占 12.1%  →  模型能区分     →  cancellation 95.5%
```

**这解释了为什么单纯增加「正例」不能提升条件判断能力** ——
正例只告诉模型「该怎么做」，不告诉它「什么时候不该做」。

## 5. 附带发现：评分口径会虚高准确率

### 5.1 漏洞

「应先追问」任务的判据是「没有 `tool_call`」。实测：

```
'请问您取消的原因是什么？'  → 判为正确  ✅ 合理
'请提供订单号'             → 判为正确  ✅ 合理
''                       → 判为正确  ❌ 空输出
```

**任何「几乎不调用工具」的模型都能近乎免费地拿到这类任务。**

### 5.2 实际影响

v3 有 15 个「应先追问」任务（占 14.2%）。未训练的基座在它们上面通过 **98.2%**（55/56），
因为它们几乎不调工具：

| | 该追问（15 个） | 该调工具（91 个） |
|---|---|---|
| baseline | 98.2%（**白拿**） | **28.0%** |
| sft_clarify | 95.5% | ~95% |

**baseline 的真实工具能力是 28.0%，不是 37.97%。** 那 14pp 差额来自这些免费分。

### 5.3 修法

`src/eval/error_taxonomy.py` 已加：**空输出判失败**（`subtype="empty"`）。

同时新增**按任务口径**的格式正确率（`format_accuracy_by_task`）——
旧口径一律要求 `tool_call`，会把「正确追问」判成格式错误（实测
`cancellation` 因此显示 0.0%，实际 ~90%）。

**教训**：任何用「未调用工具即正确」当判据的工具调用评测，都会把
**不作为**误判为**正确**。

## 6. 数据工程：训练语料必须覆盖「技能」，不只是「实体」

### 6.1 三个 0% 的根因

| 类别 | 修复前 | 修复后 | 语料缺口 |
|---|---|---|---|
| flight_search | 0% | 100% | 机场码覆盖 |
| multi_tool | 0% | 100% | **multi_tool 训练任务 0 个** |
| booking_flow | 0% | 93.3% | **带观测轮的任务 0 个** |

实测 `build_training_tasks()` 原有 181 个任务里：

```
带观测轮（多步流程）:  0 / 181
multi_tool:           0 / 181
```

**而评测有 31 个任务带观测轮、10 个 multi_tool 依赖这两项技能。** 补上后（语料 181 → 247）：

```
带观测轮:  0 → 36
multi_tool: 0 → 12
```

### 6.2 为什么实体覆盖检查抓不到

`assert_training_covers_eval_entities` 原来只查**机场码与工具**。
机场码 52/52 全绿时，技能却是 0。**现在断言同时查技能**：

```
评测有 31 个带观测轮的任务，而训练语料 0 个 —— 模型没见过「读观测再行动」
评测有 10 个 multi_tool 任务，而训练语料 0 个 —— 模型没见过「一次调两个工具」
```

### 6.3 一个反直觉的迁移

**`flight_search` 我根本没补专类语料** —— 它从 0% 涨到 100%。
原因：观测驱动的 `book_flight` 任务教会了模型「三字码来自用户话、
`flight_id` 来自观测」，这个技能迁移过去了。

