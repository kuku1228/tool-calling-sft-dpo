## A. 可以直接用（不依赖作废的性能数字）

**航空客服工具调用 Agent 的评测体系与偏好优化** ｜ 个人项目 ｜ 2025-2026

- **发现并修复了会导致全部结论作废的数据污染**：定位到 SFT 训练样本中
  **1292/2509（51.5%）的 prompt 与评测 prompt 逐字相同**（等于在测试集上做
  梯度下降），据此**主动推翻自己的主结果并重训**。
  根因不是「忘了过滤」而是**注释与代码不一致**：同一文件里
  `build_recovery_pairs` 的文档写着「评测与训练完全分离」且**它确实做到了**，
  另外三处构造器却直接吃了评测任务集 —— 那句正确的注释让所有人（包括我）
  停止了核对。修法是**四层防线**：前缀分界常量 + 越界即抛错的硬门禁 +
  默认值不再吃评测集 + 5 条回归测试。
  `docs/ablation/ablation_report.md` §8

- **把「不报错但结论是错的」这类缺陷系统性地变成可检查的断言**。
  项目里 8 个最严重的缺陷**全部不报错**：数据污染让准确率**更高**；
  2 个任务的期望参数为空导致它们**永远判成功**；一致性检查器报「✓ 一致」
  但实际一条未检查；循环导入导致 7 个测试**静默不注册**；prompt 截断
  23.2% 却报告「健康」；TRL 指标键名错（`rewards/margins` 复数）显示 NaN；
  内建 `hash()` 做种子让跨进程不可复现；PyYAML 把 `5e-05` 读成字符串。
  修法：每条都配一个**能失败的检查**，并**给检查器本身写反向测试**
  （喂入已知坏数据，确认它真的报警）。

- **量化并修正了一个统计判据错误**：长期用「两个 95% CI 是否重叠」
  判断差异显著性 —— **那是错的**，配对数据必须用配对检验。
  替换为：**任务级配对 bootstrap**（重采样单位是任务，不是样本 ——
  同一任务的多次采样高度相关）+ **McNemar 精确检验**（不用卡方：
  不一致对常 < 10，近似不可靠）+ **MDE 功效分析**。

## B. 待 v3 任务集重跑确认（**暂不要写**）

以下都是有价值的结论，但**数字必须等新实验**：

| 结论 | 为什么暂缓 | 需要什么 |
|---|---|---|
| SFT 把准确率从 X 提到 Y | 旧数字跑在 v1 任务集（日期全在过去、`multi_tool` 名不符实、13 处文本重复） | v3 上重跑 baseline + SFT |
| DPO 在追问边界上是唯一解 | 方向可信（在 β=0.1/0.5 两次运行中复现），但**有效样本是 1 个行为**（14 种触发方式） | v3 上重跑，并按**簇级口径**报告 |
| 多轮 Agent 执行循环的成功率 | 旧数字跑在 v1 上，且 agent 评测覆盖的 39 个任务**排除了 `flight_search`**（SFT 最弱的单类） | v3 上重跑 agent 评测 |
| 「DPO 崩塌源于 clarify 偏好对过度泛化」 | **这是我读一次失败得出的机制假设**，需要**剂量-反应**才能确立 | C1 实验：clarify 占比 0%/30%/100% |

**其中最后一条最能说明问题**：如果损害真由 clarify 偏好对造成，
那么在**其他条件完全相同、只改 clarify 占比**时，
`clarify_instead` 错误率应单调上升、准确率应单调下降。
**三条曲线都单调 → 机制确立；否则我的假设就是错的。**
判据已**事先写进脚本和测试**（先看结果再定判据，就总能找到说法让数据「支持」假设）。

## C. 方法论结论（可以用，但表述要准确）

- **`logps/chosen` 无法预测任务能力失效**。实测：某次 DPO 训练里它
  从 −6.17 → −4.55（**看起来很稳定**），而任务准确率同时崩了 33.75pp。
  我据此判断过「训练健康」，而模型已经崩了。
  修法：改用**轨迹级** KL 漂移（`E_policy[log p − log q]`），
  并**成对报告均值与标准差** —— 只看均值会漏掉「均值没变但分布被重构」。

- **结论的边界必须与数字一起出现**。实测的任务级 bootstrap 下：
  100 个任务能检出的最小效应 ≈ **14pp**。所以「差 3 个百分点」这类
  结论在这个规模上**不可能获得统计支持** —— 与其硬讲，不如把结论重心
  转向错误类型的结构性变化。

- **「同一期望调用的多个任务」不是独立证据**。新任务集里 106 个任务
  只有 **92 个不同的期望调用**，其中一个簇是 14 个 clarify 任务共享的
  （它们的正确答案都是「不调用工具」）。统计必须按**簇**重采样：
  实测有效样本从 101 降到 87，置信区间**变宽**（这是更保守的口径）。

## 写作注意（避免面试翻车）

| ❌ 不要写 | ✅ 应该写 |
|---|---|
| 「4 个任务 4/4 全对，证明 rejected 侧不可替代」 | 「**1 个行为**在 14 种触发方式下都被验证」（有效样本是 1，不是 14） |
| 「seen 组虚高 17.9pp」 | 不提 seen/unseen —— 该标签**已被证明没有含义**（`unseen` 组也被训练覆盖 100%） |
| 「CI 不重叠，所以显著提升」 | 「配对 bootstrap + McNemar」（CI 重叠**不是**显著性判据） |
| 「准确率从 50.25% 提升到 83.00%」 | 等 v3 重跑后再写具体数字 |
| 「agent 全面 100%」 | 若写，必须带上「评测不含 `flight_search`」这个覆盖缺口 |

**主动说明局限比被追问出来更有利。** 每条结论都准备一句
「这个数字的边界是……」，而**边界不清楚的结论就不要写**。
